# 03. Design

| # | 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|---|
| 1 | 백엔드 - FastAPI | Django, Express | 비동기 지원, 타입 힌트 기반 자동 검증/문서화로 소규모 API에 적합 | Django 대비 배터리 포함(admin, ORM 등) 기능 부족, Express 대비 Python 생태계 한정 |
| 2 | 프론트 - Vanilla JS + Tailwind CDN | React, Vue | 별도 빌드 도구 없이 즉시 실행 가능. 프론트는 백엔드가 같은 오리진에서 제공하며 file://로 직접 열지 않음 | 컴포넌트 재사용/상태관리 편의성은 React, Vue보다 낮음 |
| 3 | DB - SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 별도 서버 설치 없이 파일 기반으로 즉시 개발 가능, ORM으로 추후 전환 경로 확보 | 동시 쓰기 성능 및 다중 사용자 확장성은 PostgreSQL보다 낮음 |
| 4 | CSS - Tailwind만 | styled-components 등 | 유틸리티 클래스로 빌드 없이 빠른 스타일링, CDN 방식과 궁합이 좋음 (styled-components 금지) | 클래스명이 길어져 마크업 가독성 저하 가능 |
| 5 | 실시간 - MVP는 폴링 3초 | WebSocket | 구현이 단순하고 인프라 부담이 적음. WebSocket은 확장 단계로 보류 | 실시간성이 떨어지고 불필요한 요청이 반복 발생 |
| 6 | 상태관리 - 모듈 변수 + DOM 직접 갱신 | 상태관리 라이브러리 도입 | Vanilla JS 2파일 구조에 맞는 최소 구성, 별도 러닝커브 없음 | 상태가 커지면 추적/디버깅이 어려워짐 |
| 7 | 디자인 시스템 - Mac OS UI 톤 | Material, Ant | 둥근 모서리·반투명 카드·부드러운 그림자로 제품 요구 톤(01-product.md)과 일치 | 기성 컴포넌트 라이브러리 대비 직접 구현할 요소가 많음 |
| 8 | 테마 - 라이트/다크 토글, localStorage, 초기값은 시스템 설정 | 서버 저장 방식 | 로그인 없는 MVP에서 클라이언트 단독으로 간단히 구현 가능 | 기기/브라우저를 바꾸면 설정이 유지되지 않음 |
